# RELEASE NOTES

## v1.6.0 — 2026-08-04 (Event Log + удалённый доступ к БД)

### Вся переписка теперь пишется в БД
Раньше в базе лежала только маршрутизация — маппинг message_id и метаданные юзеров. Тексты сообщений жили только в Telegram-группе, и посмотреть «что спрашивают и как саппорт отвечает» можно было только глазами по топикам. Добавлена таблица `event_log` — плоский audit-trail каждого события.

Пишутся: сообщения клиента (`client_message`), reply саппорта клиенту (`support_reply`), переписка саппортов внутри топика без reply (`support_internal` — новый log-only хендлер в отдельной handler-группе PTB), автоответы бота в DM (`bot_message` — и `/start`-приветствие, и «ok, скоро ответим!»), создание топика (`topic_created`) и любые упавшие хендлеры через новый глобальный `add_error_handler` (`error` с traceback).

Медиа логируются как placeholder в `text` (`[photo]`, `[voice 23s]`, `[document file.pdf 1.2MB]`) плюс Telegram `file_id` — сами файлы не скачиваем, оригинал восстанавливается через Bot API `getFile`. Утилита `log_event(...)` в `database.py` оборачивает INSERT в try/except: аудит-лог никогда не ломает основной флоу.

**Схема `event_log` намеренно 1-в-1 с zorion-helpbot**, чтобы один и тот же аналитический SQL работал на обоих ботах. Колонка `email_message_id` здесь всегда NULL (в Calink нет email-канала) — оставлена ради совместимости запросов.

### Эндпоинт `/admin/db` и `scripts/fetch_db.sh`
У бота появился HTTP-сервер (aiohttp) в том же event-loop, что и polling: поднимается из `post_init`, останавливается из `post_shutdown`. Эндпоинты:
- `GET /admin/db` — live-снапшот SQLite через sqlite3 backup API (безопасно при работающем боте, без блокировок). Авторизация — Bearer-токен против списка в env `ADMIN_DB_TOKENS` (через запятую, один токен на человека, отзыв = удалить из env). Без токенов возвращает 503.
- `GET /health` — liveness.

В `scripts/fetch_db.sh` — однострочник: ставишь свой `CALINK_BOT_DB_TOKEN`, запускаешь, получаешь `support_bot.db` рядом и сводку по `event_type`. Дальше SQL по локальной копии.

Новые env: `ADMIN_DB_TOKENS`, `ADMIN_PORT` (на Railway порт подставляется через `PORT` автоматически). Новая зависимость: `aiohttp>=3.9`.

**⚠️ Нужен volume.** `DATA_DIR` берёт `/data` только если каталог существует, иначе кладёт БД рядом с ботом — в эфемерную ФС контейнера, которая стирается при каждом редеплое. Для маппинга ID это было терпимо, для архива переписок — нет. Убедись, что у Railway-сервиса примонтирован volume в `/data`.

**PII-предупреждение:** в `event_log` полные тексты сообщений клиентов и их имена. Токены раздавать только через secure-канал (1Password / Signal), снапшоты не коммитить и не пересылать в чаты.

### Известные пробелы
- Правки сообщений (`handle_edited_support_message`) и удаления (`/del`) в `event_log` не пишутся — паритет с zorion-helpbot, где их тоже нет. Если понадобится полная история изменений — добавлять отдельно в обоих ботах.
